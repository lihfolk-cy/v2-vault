Voxel art (everything built from cubes on one grid) suits Roblox unusually well: it echoes the platform's brick heritage, it can be generated by script, and it reads clearly on phones. It also has specific technical problems: part counts explode, flat cubes look plain without surface detail, and models blur into the background without outlines. This note collects the techniques one production game used to build voxel showpieces, stations and a 49-model enemy roster, and the three style kits it studied from other studios' devlog videos (described here without naming them).

## Three style kits

| Kit | Look | Use for |
|---|---|---|
| **Dark body, neon lines** (tiered) | Near-black bodies tinted to a theme hue, neon tracing edges and glyphs, a hero crown, rubble skirt and floaters at higher tiers | Premium, themed or tiered objects: stations, gates, pedestals, top-rarity showpieces |
| **Outlined toy-box** | Saturated mid-dark bodies, gold trim, one neon colour, a near-black outline round every part, raised square studs on every cube | Things the player fights or wears: enemies, bosses, armour sets, vehicles |
| **Cute pastel companions** | Light pastel bodies in one hue, one shared face recipe, an orbit element (ring, disc, sparkles), slow float | Things the player owns or likes: pets, mascots, friendly NPCs |

Rules shared by all three: one grid grain per model with visible steps; one main hue per model, one neon colour, plus white or gold as set-wide accents; eyes or the hero glow are the brightest pixels; the silhouette must be identifiable as a filled black shape; merge parts per colour group; Neon parts never cast shadows. The writing format for such guides is in [[Environment Art Styles]].

### Numbers from the studies

- **Grain:** smallest cubes about 1/40 to 1/60 of the object's longest dimension; for a 20-stud object, about 0.3 to 0.5 studs. Keep cells at or above about 0.3 studs or part counts explode.
- **Glow coverage** (dark-body kit): 1 to 5 percent at tier 1, 5 to 10 percent mid, 10 to 16 percent at the top; above about 16 percent the shape dissolves into bloom. Outlined toy-box kit: neon 3 to 8 percent of the model.
- **Cells per object** (dark-body kit, 20-stud object at 0.4-stud grain): 300 to 500 at tier 1, up to 2,000 to 3,000 at the top.
- **Characters:** large characters about 40 to 50 cells tall; vehicles 60 to 80 cells long.
- **Particles:** voxel cube particles 0.05 to 0.3 studs, about 20 to 40 alive per object; floaters 0.5 to 2 studs, 3 to 10 per object, each with its own bob phase.

## Building voxels in Studio: merge per colour

A naive voxel build makes one Part per cell: a 2,000-cell object becomes 2,000 Parts. Merging runs of same-colour, same-material cells into longer Parts cuts that dramatically. One production game's voxel kit merged runs along X only and turned a 1,216-cell test pedestal into 459 Parts; a second pass merging equal X-runs along Z cuts further.

```lua
--!strict
-- Greedy voxel merge: cells keyed "x,y,z" -> {color, neon}. Merges runs along X, then merges
-- identical X-runs along Z into rectangles. Builds one Part per rectangle.
type Cell = { c: Color3, neon: boolean }

local function key(x: number, y: number, z: number): string
	return x .. "," .. y .. "," .. z
end

local function same(a: Cell?, b: Cell?): boolean
	return a ~= nil and b ~= nil and a.c == b.c and a.neon == b.neon
end

local function build(cells: { [string]: Cell }, bounds: { min: Vector3, max: Vector3 },
	origin: CFrame, size: number, parent: Instance): number
	local used: { [string]: boolean } = {}
	local count = 0
	for y = bounds.min.Y, bounds.max.Y do
		for z = bounds.min.Z, bounds.max.Z do
			for x = bounds.min.X, bounds.max.X do
				local k = key(x, y, z)
				local cell = cells[k]
				if cell and not used[k] then
					-- 1) extend along X
					local lenX = 1
					while same(cells[key(x + lenX, y, z)], cell) and not used[key(x + lenX, y, z)] do
						lenX += 1
					end
					-- 2) extend the whole run along Z while every cell matches
					local lenZ = 1
					while true do
						local ok = true
						for i = 0, lenX - 1 do
							local kk = key(x + i, y, z + lenZ)
							if not same(cells[kk], cell) or used[kk] then
								ok = false
								break
							end
						end
						if not ok then break end
						lenZ += 1
					end
					for i = 0, lenX - 1 do
						for j = 0, lenZ - 1 do
							used[key(x + i, y, z + j)] = true
						end
					end
					local p = Instance.new("Part")
					p.Anchored, p.CanCollide, p.CanQuery, p.CanTouch = true, false, false, false
					p.TopSurface, p.BottomSurface = Enum.SurfaceType.Smooth, Enum.SurfaceType.Smooth
					p.Size = Vector3.new(size * lenX, size, size * lenZ)
					p.CFrame = origin * CFrame.new(
						(x + (lenX - 1) / 2) * size, (y + 0.5) * size, (z + (lenZ - 1) / 2) * size)
					p.Color = cell.c
					p.Material = if cell.neon then Enum.Material.Neon else Enum.Material.SmoothPlastic
					p.CastShadow = not cell.neon
					p.Parent = parent
					count += 1
				end
			end
		end
		task.wait() -- one layer per frame keeps Studio responsive
	end
	return count
end
```

Notes:
- Colours must be **exactly** equal to merge; quantise colours (a palette) before building, or tiny differences block merges.
- Merged parts are visual only (`CanCollide = false`); add a few collider blocks.
- For anything repeated in the world, go further: **bake the voxel model in Blender into one mesh per colour** (below).

## Voxel meshes: one mesh per colour

For stations, enemies and anything repeated, the production approach was to generate the voxel model in Blender (Python), delete interior faces, and export **one mesh per colour**. In Studio each mesh keeps its `Color`, uses a built-in Material, and shares one stud SurfaceAppearance. A station of ten colours becomes ten MeshParts regardless of how many cubes it has, and every station shares the same overlay texture.

Enemy rebuild numbers: 49 models at 10,000 to 42,000 triangles each, roughly 30 parts per model with the largest about 6,500 triangles, a 0.5-stud voxel grain (a boss 58 cells tall). Triangle counts were similar to the earlier stud-geometry builds once studs moved into textures.

## Studs: surface detail without geometry

Raised square studs on every cube are the signature of the toy-box look: they give scale, texture and a classic Roblox feel. Options, best first:

| Option | How | Pros | Cons |
|---|---|---|---|
| A. Stud **normal map** | Tiling normal map (plus faint matching colour map, ColorMap white) in a SurfaceAppearance, 1 tile = 1 cell | Responds to real light; zero geometry; part colour tints it | Needs UVs at cell scale; SurfaceAppearance only on MeshParts |
| B. Baked stud **overlay** | Mostly transparent image with lit edge and shadow painted in, `AlphaMode = Overlay` (meshes) or a `Texture` (parts) | Works on Parts too; one image for every colour | Lighting baked, does not react to the sun |
| C. Modelled studs baked to normals | Inset and extrude 10 to 15 percent per face in Blender, bake to a normal map | Most accurate | Only for heroes |
| Real stud geometry in game | Studs as geometry | Real | About 20 extra triangles per stud face: never for in-game meshes |

Stud parameters that read well in the studies: one square stud per cell, about 40 to 50 percent of the cell width, height about 10 to 15 percent; lit rim 10 to 20 percent lighter than the face, shadow side 15 to 25 percent darker. In the enemy rebuild: studs 44 percent of the cell, lit top/left rim x1.32, shaded bottom/right rim x0.62, cap x1.07, a soft drop shadow.

**Where studs stop:** neon (eyes, bands, lamps), glass and special metal stay **smooth**. The contrast between studded body and smooth glow reads as "special material" and should be used on purpose.

On parts (environment ground), the production overlay held 4 x 4 studs per 8 x 8-stud tile, applied as a `Texture` with `StudsPerTile` 8 on up-facing faces only. See [[Textures Decals and Texture Memory]] and [[Materials MaterialVariants and SurfaceAppearance]].

## Shading: three tones per material

Voxel models look muddy with long colour ramps. The enemy rebuild settled on **three tones per material**: shadow (dark mixed about 45 percent toward the body colour), body, and lit top (body mixed about 40 percent toward light), with colour jitter off. Its earlier five-step ramps made yellow read olive. Lines (dark seams) went only where **parts or materials meet**; lines on every block step made curved parts dark and noisy.

## Outlines

A near-black contour (about 1 cell, colours around #060808 to #0a0b17) round every part makes voxel models read in busy fights. Options:

| Method | Cost | Notes |
|---|---|---|
| Inverted hull baked into the mesh (Blender Solidify, flipped normals, black back-face-culled material; 0.16 studs worked on a 0.5-stud grain) | **Doubles triangles** | Works everywhere, any count; use on bosses and heroes |
| `Highlight` with `FillTransparency = 1`, near-black `OutlineColor`, `DepthMode = Occluded` | Per-highlight render cost | Limited number on screen (see note below); good for bosses and the local player |
| Part-seam lines in the texture/vertex colours | Free | What carried the look in game for the 49-enemy roster |
| No outline, strong value contrast against the sky | Free | Fine for calm, uncluttered scenes |

The reference project's notes say Roblox limits about 31 active Highlights; the current Roblox highlighting guide says Studio displays at most **255** simultaneous client-side Highlights and silently skips extras (October 2026). Either way, Highlights are not a crowd solution; check the current limit and cost before relying on them. See [[Highlights and Selection Effects]].

The enemy roster kept the thick outline in preview renders only: in game it would have doubled triangles across 49 models.

## Reskinning many models at once

The 49-model enemy rebuild is a good template for any bulk art replacement:

1. **Keep everything that is not the look.** Each slot kept its id, skeleton (bones, pivots, root), animation clips, AI role, zone and attacks. Only meshes changed, so gameplay code needed no edits.
2. **A brief and a shared library.** One written brief for every design (style rules, palettes, three-tone ramps, stud atlas, seam rules), one shared Python helper library, one script per model.
3. **Previews and a contact sheet.** Front, side and three-quarter renders per model, plus one contact sheet of all 49 at the same scale, reviewed before any upload.
4. **Installer that re-measures.** The install step rebuilt each rig from a manifest and re-measured ground offsets (root height, hover height for flyers); fit error was checked on every rig.
5. **Mark and back up.** Every new model carried an attribute with the rebuild date; the previous models were kept as one copy in storage and in version history.
6. **Size is gameplay.** Restyled regulars grew to a 13-stud target (players about 9), with hit shapes scaling with them; bosses were not resized. Size changes need a playtest pass for hit ranges, not just a visual check.
7. **Verify saves.** Cloud saves timed out repeatedly during the work and the place once reopened at an older version; confirm a clean save before calling bulk art done ([[Version History and Backups]]).

See [[Case Study - Enemy Roster Rebuild]] and [[Pipeline - Importing Animated Enemies]].

## Motion and effects in voxel styles

- **Effects are voxel objects too.** Cube particles (tiny Parts or a ParticleEmitter with a square texture), crystals, rings and planets as small voxel builds that bob, spin and orbit.
- **Glow comes from Neon plus bloom**, not glow sprites, so edges stay crisp and blocky.
- **Everything has its own phase**; floaters never bob in sync.
- **Budget it:** cap cube particles at about 40 alive per object with one shared update loop, pause beyond about 150 studs, halve on low graphics settings, and switch to ParticleEmitters when many objects are visible. See [[Particle Emitters In Depth]].

## Common mistakes

| Mistake | Result | Fix |
|---|---|---|
| One Part per cell | Thousands of parts | Greedy merge per colour; bake to meshes |
| Near-identical colours | Merges blocked | Quantise to a palette |
| A smooth sphere or cylinder slipped in | Breaks the voxel read | Voxelise everything |
| Grey bodies on dark themes | Unfinished look | Tint dark colours to the hue |
| Too much neon | Shape lost in bloom | Stay inside glow budgets |
| Real stud geometry | Triangle explosion | Normal map or overlay |
| Lines on every step | Dark, noisy curves | Lines only at part/material seams |
| Outline hulls on crowds | Double triangles everywhere | Bosses only; seams for the rest |
| Bulk reskin that also changes rigs | Broken animations and AI | Change only the look |

## Checklist

- [ ] Kit chosen per asset class; style guide written.
- [ ] One grain per model; cells at or above about 0.3 studs.
- [ ] Palette quantised; merged per colour; colliders separate.
- [ ] Repeated models baked to one mesh per colour with a shared stud SurfaceAppearance.
- [ ] Studs via normal map or overlay; glow, glass and metal smooth.
- [ ] Three tones per material; seams only where parts meet.
- [ ] Outlines only where the budget allows.
- [ ] Bulk reskins keep ids, rigs, clips and roles; contact sheet reviewed; saves verified.
