One line per note in `10 Game Design and Genres`: title, then the first TL;DR bullet (or the first sentence).
Generated by `_tools/build_index.py`; open a note's TL;DR block before reading it.

- Balancing with Spreadsheets and Data: Avoid: Typing derived numbers by hand -> Formulas from inputs; only inputs are typed
- Boss Fight Design Patterns: Avoid: Fixed boss health -> Scale to group damage; target TTK
- Core Loops and Session Design: Avoid: Designing systems before the verb feels good -> Prototype the verb alone first
- Ethical Design and Player Trust: Avoid: "Everyone does it" as the justification -> The parent test
- First-Time User Experience and Onboarding: Avoid: Text walls ("Welcome to the world of...") -> One line, one target, one pointer
- Genre Playbook - Battlegrounds and Arena Fighters: Avoid: Server-only hit decision with no rewind -> Lag-compensated server checks, capped
- Genre Playbook - Combat and RPG: Avoid: Tuning damage without a TTK target -> TTK per enemy type per zone in the sheet
- Genre Playbook - Horror and Story: Avoid: Constant jump scares -> Build, spike, release
- Genre Playbook - Obbies and Platformers: Avoid: Hard jumps in the first 10 stages -> Comfortable band early; spikes later
- Genre Playbook - Party and Minigame Collections: Avoid: Long intermissions -> 10 to 20 s, with things to do
- Genre Playbook - Puzzle and Escape Rooms: Avoid: Answers stored on the client -> Answers in server-only storage
- Genre Playbook - RNG and Collection Games: Avoid: Hand-typed "1 in N" that do not match the algorithm -> Derive displayed odds from the rolling code
- Genre Playbook - Racing and Driving: Avoid: Server-owned driven cars -> Driver owns the car; server owns idle cars
- Genre Playbook - Roleplay and Social Hangouts: Avoid: A huge, empty map -> Dense story locations, vehicles, teleports
- Genre Playbook - Shooters FPS and TPS: Avoid: Trusting the client's "I hit X" -> Server validation with capped rewind
- Genre Playbook - Simulators: Players stop at zone 3 to 5: Zone price outruns income; no new reason to push -> Re-price in minutes of income; add a visible reward per zone
- Genre Playbook - Sports: Avoid: A plain unanchored ball, owned by whoever touched it last -> Possession model with server-decided flight
- Genre Playbook - Survival and Crafting: Avoid: Persistent shared world as a first project -> Run-based or per-player bases first
- Genre Playbook - Tower Defense: Avoid: Humanoid NPC enemies -> Data-driven enemies, client-rendered
- Genre Playbook - Tycoons: Avoid: Physical parts for every drop on the server -> Server income tick; client-only visual drops
- Progression and Pacing Design: Avoid: Matching cost and reward multipliers exactly -> Let T rise slowly, then drop at milestones
- Rarity Ladders and Drop Pacing Math: Avoid: Pacing on the mean -> Pace on the median and the p90
- Retention and Return Hooks: Avoid: Trusting the client clock -> Server `os.time()` only
- Simulator and RNG Genre Teardown: Avoid: Copying features without measuring clocks -> Stopwatch log first, feature list second
- Social Design and Multiplayer Play: Avoid: Social features that need 10 players in a server of 3 -> Design for low density first; scale up with events
